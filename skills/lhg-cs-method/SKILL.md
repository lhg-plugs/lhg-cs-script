# lhg-cs-method：客服话术方法论

## 1. 何时使用

- 从 0 到 1 搭建客服话术库时
- 高频场景靠客服临场发挥，回复质量不稳定时
- 新客服培训，需要一套"照着说不出错"的话术时

**不适用**：只需要单条回复润色（直接改那句话就行，不用整套方法论）。

## 2. 输入与输出

**输入**：业务类型、高频场景清单、用户画像、现有话术痛点。
**输出**：按场景分节的话术库文档（每节四段式话术 + 转人工触发条件）+ 话术更新机制。

### 2.1 场景澄清（最多 5 个问题）

1. 业务类型是什么？（电商/ SaaS /本地生活…）
2. 高频场景 Top5 是什么？（按咨询量排序）
3. 用户画像？（年龄/付费习惯/情绪特点）
4. 现有话术最大痛点？（回复慢/口径不一/投诉多…）
5. 客服团队规模与权限？（能否直接退款/补偿，额度多少）

## 3. 四段式话术结构

每条场景话术都按"安抚 → 解释 → 补偿 → 转人工"四段组织：

### 3.1 安抚（先接住情绪，再谈事情）

- 顺序铁律：**情绪先于事实**。用户带着情绪来，先谈事情等于火上浇油。
- 公式："称呼 + 具体共情 + 接管承诺"
- 好："亲，等了 5 天还没发货，换我也着急，这个问题我来跟进。"
- 坏："亲，我理解您的心情。"（空话：理解什么了？）

### 3.2 解释（用户语言说原因）

- 用用户能听懂的话说原因，不说黑话（"系统异常"不如"仓库那边单子卡住了"）。
- 只解释一次，不反复辩解；解释完立刻转向解决方案。
- 不许推诿："这是仓库的问题" → 改为"仓库那边出了点状况，我已经在催了"。

### 3.3 补偿（方案 + 条件 + 时限）

- 三要素缺一不可：给什么方案、在什么条件下、什么时候兑现。
- 好："审核通过后 3 个工作日内原路退款，超时我亲自跟进。"
- 坏："我们会尽快处理。"（多快？谁跟进？都没说）
- 补偿涉及成本：必须注明审批流程（如"补偿需主管审批"），不许写超权限的承诺。

### 3.4 转人工（触发条件写进话术）

- 每类话术末尾写清"出现以下情况转人工"（见 lhg-cs-escalate）。
- 转接话术模板："这个问题我需要请专员协助，我先把您的情况完整记录，转接后您不用重复描述。"

### 3.5 话术语气标尺

同一句话，三种语气，效果天差地别。写话术时对照标尺：

| 标尺 | 示例（催用户提供信息） | 效果 |
|---|---|---|
| 生硬 | "请提供您的订单号，否则无法处理。" | 用户觉得被命令 |
| 标准 | "麻烦您提供一下订单号，我来帮您查。" | 过得去，无感 |
| 共情 | "亲，麻烦您报一下订单号，我这就去查，查到马上告诉您。" | 用户愿意配合 |

**标准**：所有对外话术至少达到"标准"档，投诉/差评场景必须"共情"档。

## 4. 高频场景梳理方法

1. 拉最近 30 天咨询记录，按问题归类计数
2. 取 Top5-8 场景先写话术（覆盖 80% 咨询量即可先行上线）
3. 每个场景标注：咨询占比、平均处理时长、投诉转化率
4. 投诉转化率高的场景优先写，哪怕它不在 Top5

## 5. 补偿分级表（示例框架，按业务调整）

| 级别 | 场景 | 补偿 | 审批 |
|---|---|---|---|
| L1 | 轻微不便（回复慢、页面小 bug） | 道歉 + 优惠券 | 客服自主 |
| L2 | 明确损失（发错货、延迟 3 天+） | 退款/重发 + 补偿 | 客服自主（限额内） |
| L3 | 严重损失（贵重物品丢失、数据丢失） | 全额赔付 + 书面说明 | 主管审批 |
| L4 | 群体性/舆情风险 | 专项方案 | 负责人审批 |

**原则**：补偿标准对内透明、对外不主动报价（用户问再按级给，避免"会哭的孩子有奶吃"）。

## 6. 话术自查清单（人工项）

- [ ] 每条话术大声读一遍：拗口、像机器人、像念条文的，重写
- [ ] 安抚段是否"具体"（说出了用户的具体处境，而不是"我理解"）
- [ ] 解释段是否只说一次、有没有推诿句式
- [ ] 补偿段三要素（方案/条件/时限）是否齐全
- [ ] 转人工触发条件是否写清
- [ ] 全文扫一遍禁用语与过度承诺（跑审计脚本）

## 7. 话术更新机制

- 新场景出现 → 按四段式增补一节，标注日期与版本
- 每月复盘：看"话术覆盖率"（命中话术的咨询占比）与"投诉转化率"
- 废话术退役：连续 30 天零命中的话术移入归档，不删（留作记录）
- 大促/版本更新前：提前 7 天增补相关话术，不许临时抱佛脚

## 8. 反模式（不要这么做）

1. **话术写成免责声明**：满篇"最终解释权归本公司" —— 用户要的是解决，不是普法。
2. **一套话术打天下**：退款话术和咨询话术用同一套 —— 场景不同，四段比重不同。
3. **补偿拍脑袋**：客服临场决定赔多少 —— 没有分级表，补偿就是糊涂账。
4. **只写话术不写转人工**：客服被超出权限的问题卡住，只能硬扛或瞎承诺。
5. **话术写完就封存**：业务变了话术不变，三个月后话术库就是废纸。

## 8.5 常见问题

**Q：团队只有 2 个客服，话术库要写多细？**
A：先写 Top5 场景，每个场景一页纸（四段式各 2-3 句）。覆盖 80% 咨询量就先上线，剩下的在复盘中增补。完美的话术库是迭代出来的，不是一次写出来的。

**Q：话术和客服个人风格冲突怎么办？**
A：话术定"底线"（不许说的、必须说的），风格给自由。客服可以在四段式框架内用自己的话说，只要三要素齐全。把客服管成复读机，话术越标准，用户越觉得假。

**Q：AI 客服能用这套话术吗？**
A：能。四段式结构天然适合做 AI 客服的回复模板：安抚段做情绪识别后的首句，补偿段接规则引擎。注意给 AI 话术加"置信度门"——拿不准的场景转人工，别让 AI 瞎承诺。

**Q：补偿分级表定多少额度合适？**
A：看两个数：客单价和投诉率。L1/L2 客服自主额度一般设为"客单价的 10%-30%"，超过的升级。定完跑一个月，看"补偿成本占比"和"投诉解决率"再调。

## 9. 自检与反馈

**质检门**：

- [ ] Top5-8 高频场景全覆盖，每节四段式完整
- [ ] 补偿分级表已按业务填写，审批链清晰
- [ ] 转人工触发条件每节都有
- [ ] 审计脚本 blocker 清零
- [ ] 已定好每月复盘的负责人与时间

**标准冒烟用例**：`python3 scripts/audit/cs_audit.py --target <话术库目录>`，blocker 清零。
